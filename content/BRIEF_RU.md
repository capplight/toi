## 1. Задача

Написать **все тексты интерфейса на русском** для веб-продукта «Той» — по ключам из `content/messages/_keys.json`. Русский — второй язык (по умолчанию включён казахский), на нём работают русскоязычные родители, молодые и гости в Казахстане.

Пишите естественным русским языком хороших приложений (банки, госуслуги, сервисы доставки), с учётом казахстанской речи: той, төр, құдалар, асаба — это обычные слова для аудитории (см. глоссарий). **Не переводите с казахского дословно**: смысл берите из контекста ключа (`_context.json`, колонка «Где» в инвентаризации), а не из kk-строки. Смысл и объём информации в kk и ru должны совпадать, формулировки — нет.

Сейчас русского текста нет у **481 строки из 764**: русские тексты есть только у экранов v1 (список, добавление гостя, зал). Все новые экраны — вход, мастер, составители, страница гостя, итоги, расходы, помощник, рассылка — пишутся с нуля. Существующие ru-тексты нужно вычитать: часть из них грамматически не работает, когда «семья» — это один человек.

## 4. Что сдать

1. **`content/messages/ru.json`** — копия `_keys.json`, в которой **заполнены все значения**. Ключи не добавлять, не удалять, не переименовывать.
2. **`content/NOTES_RU.md`** — заметки (формат в разделе 6).

### Формат `ru.json`

- JSON в UTF-8, вложенные объекты, как в `_keys.json`. Отступ 2 пробела.
- Значения — ICU MessageFormat (next-intl). Переменные — ровно те, что в колонке «Переменные»; имена не менять.
- **Все числа с существительными — через `plural` с ветками `one`, `few`, `many`, `other`** (ветка `other` обязательна — для дробей): `{count, plural, one {# место} few {# места} many {# мест} other {# места}}`.
- Где число + существительное в косвенном падеже («не хватает … мест», «для … человек»), подбирайте формы под падеж: `{missing, plural, one {# места} few {# мест} many {# мест} other {# места}}`.
- Варианты по типу тоя — `select`: `{kind, select, uilenu_toi {…} kyz_uzatu {…} sundet {…} besik {…} merey {…} other {…}}`.
- Переносы строк (WhatsApp, SMS) — `\n`.
- ASCII-апостроф `'` не использовать (ломает ICU). Кавычки — «», вложенные „“.
- Разметка — только теги next-intl: `<b>…</b>`, `<link>…</link>`.

Пример:

```json
{
  "guests": {
    "list": {
      "total": "Всего: {families, plural, one {# семья} few {# семьи} many {# семей} other {# семьи}} · примерно {seats, plural, one {# место} few {# места} many {# мест} other {# места}}"
    }
  },
  "guestSheet": {
    "delete": {
      "confirm": "Удалить из списка?\n{name}",
      "toast": "Удалено: {name}"
    }
  },
  "invite": {
    "date": {
      "countdown": "{days, plural, =1 {Той завтра} one {До тоя # день} few {До тоя # дня} many {До тоя # дней} other {До тоя # дня}}"
    }
  }
}
```

Пустые значения не оставляйте: если строка кажется лишней, дайте лучший короткий вариант и объясните в заметках.

## 8. Чего не делать

- Не переводить kk-строки дословно. Не переносить казахский порядок слов и конструкции.
- Не склонять и не согласовывать по роду переменные (`{name}`, `{eventTitle}`, `{category}`, `{label}`, `{member}`).
- Не писать «Вы» с прописной, «(а)», «он(а)».
- Не транслитерировать казахские слова («Кыз узату», «кудалар», «тор»): либо русское слово, либо казахское в казахской орфографии — по глоссарию.
- Не придумывать функции, которых нет.
- Не использовать религиозные формулы и эмодзи.
- Не менять ключи и имена переменных.
- Юридические строки (`legal.*`, `invite.rsvp.consent`, `wizard.music.rights`) — только понятный черновик с пометкой «ЮРИСТ».
