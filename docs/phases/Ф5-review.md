## 4. Решения по проблемам из handover

1. **Замер `guests-perf` (S1 < 1 с при CPU ×4) падает локально: медиана 3,5–5 с.** Не блокирует Ф5.
   - Ф5 почти не меняет S1 (+2,7 КБ сообщений).
   - Почти пустая страница «Зал» на той же машине замедлилась так же, в ~4 раза, а без замедления CPU цифры прежние. Значит, машина, не код.
   - Проверка — **CI на Linux**, тест там остаётся обязательным (как решено в ревью Ф4), и **реальный недорогой Android** в РА.
   - Локально — добавить калибровку: тест сначала меряет каркас «Зал» и пишет отношение S1 / каркас в журнал. Если каркас медленнее 0,5 с, тест помечается «машина перегружена» и не падает, а только пишет цифры. Тогда локальные прогоны не дают ложных падений, а CI остаётся строгим.
2. **Полный набор e2e не перезапущен** — П2.

## 5. Неблокирующие замечания

- **Н1.** Гонка «срок ответа истёк между загрузкой страницы и записью» мала: проверка `closesAt` идёт до транзакции. Для чистоты перенести её внутрь шага `withSeating`.
- **Н2.** Лимит обработки музыки: не больше 10 `finalizeUpload` в час на пользователя (`rate_limits`).
- **Н3.** `/api/upload` (только `local`) читает тело целиком до проверки размера — допустимо для драйвера разработки; при П1 он в проде недоступен.
- **Н4.** Музыка на странице: при драйвере `s3` у файла уже есть `Cache-Control: immutable`, но presigned URL каждый раз новый, поэтому браузер скачивает файл заново при каждом визите. Для пилота нормально. В KZ — публичный бакет только для музыки или CDN.
