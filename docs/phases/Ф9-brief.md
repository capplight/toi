## 1. Цель

Хозяин и родители видят, сколько потрачено и сколько осталось, по категориям и по срокам оплат. Они ведут статьи расходов. Сумма ресторана считается сама из подтверждённых мест.

## 2. Данные и правила

| Тема | Решение |
|---|---|
| Таблица | `expenses` как есть: категория (8 значений), `title` 1–80, `planned_amount` / `paid_amount` ≥ 0 (целые тенге), `due_date`, `note` ≤ 500, `linked_to_seats`, `created_by`, `updated_by`, `updated_at` |
| Бюджет | `events.budget_total` (может быть пусто → `#nototal`, без полосы) |
| **Ресторан** | Одна статья события с `linked_to_seats = true`, категория `restaurant`. Её **план не хранится, а считается при чтении**: `price_per_seat × Σ confirmed_count` у семей «Келеді» (`confirmed`), то есть пересчитывается после каждого ответа. Оплачено и срок — редактируемые. Цена места — `events.price_per_seat` (поле «Бір орынның бағасы»); пока её нет — `budget.restaurant.priceMissing`. Единственность такой статьи — в сервисе: создание и изменение под блокировкой строки события (`for update`). Миграция не нужна |
| Одновременная правка | Оптимистично по `updated_at`: клиент передаёт значение, которое видел; не совпало → 409 и свежие данные (`settings.conflict` или `errors.conflict`) |
| Удаление | Настоящее удаление + тост `budget.item.deletedToast` с «Қайтару» на 8 с. Отмена создаёт статью заново из снимка, который вернул сервер (тот же `id`, если свободен). Снимок проверяется так же, как при создании |
| Суммы | `Intl.NumberFormat` (`kk-KZ` / `ru-RU`, без дробной части) + « ₸», неразрывные пробелы (DESIGN 17.3). Ввод суммы — цифры с любыми пробелами, ошибка `budget.item.errors.amount` |
| Даты | «Жақын төлемдер»: статьи с `due_date` и `paid < planned`, по возрастанию даты. Просроченные (раньше «сегодня» по `Asia/Almaty`) — красная плашка + `budget.upcoming.overdue` |
| Кто менял | `budget.item.changedBy`: подпись составителя (`updated_by` → `event_members.label` / `display_name`) и дата |

## 4. Тесты

- **integration:**
  - доступ: хозяин и родитель ✓; «Жастар», «Басқа» без права и чужой — 403 на каждое действие и на `budgetView`;
  - ресторан: план = цена × подтверждённые места; меняется после `recordAnswerByMember` и ответа гостя; цены нет → `priceMissing`; второй `linked_to_seats` не создаётся (параллельные вызовы — под блокировкой);
  - 409 по `updated_at`;
  - удаление и восстановление;
  - суммы ≥ 0 и только целые; итоги и перерасход; «просрочено» по Алматы.
- **e2e (360, 320, 1440; kk и ru):**
  - хозяин задаёт бюджет и 3 статьи, видит полосы и ближайшие оплаты;
  - мама (родитель) меняет «Төленді» → «Анасы өзгертті»;
  - «Жастар»: пункта нет, прямой заход → `#noright`;
  - ресторан пересчитывается после ответа гостя через `/i/{token}`;
  - удаление с «Қайтару»;
  - axe, 130 %.
- Критерий из плана: хозяин вносит 10 статей за 5 минут (ручная проверка; замер — в handover).

## 5. Критерии приёмки

1. Права по Р9: хозяин и `can_manage_budget` — всё; остальным 403, пункта нет.
2. Ресторан считается из подтверждённых мест и цены места и пересчитывается без действий человека.
3. Экран по 8.20 и макету 13 (все состояния), суммы с неразрывными пробелами, без круговых диаграмм.
4. Одновременная правка не теряет данные (409); удаление отменяется.
5. Карточка на «Қорытынды» с суммами.
6. Все проверки зелёные; миграций нет.
