## 4. Файлы дизайна v2.2 (сейчас не закоммичены)

Изменения дизайнера (`design/DESIGN_v2.md`, `design/v2/index.html`, новые и обновлённые `design/v2/screenshots/*.png`) должны попасть в репозиторий **отдельным коммитом с документами в `main`**, не в ветку фазы. Порядок (делает разработчик по просьбе основателя или сам основатель):

```
git switch main                      # изменения в design/ переедут вместе с рабочей папкой (ветка фазы их не трогает)
git status design/                   # проверить: только файлы дизайнера, исходники обложек (design/v2/covers/source/) не попадают — они в .gitignore
git add design/
git commit -m "docs(design): DESIGN v2.2 — spec, gallery, screenshots"
git switch phase/F0-setup
git rebase main                      # ветка фазы снова «поверх» main; в PR остаются только изменения Ф0
```

Правило на будущее (добавить в `AGENTS.md` при следующей правке): документы дизайнера, контент-лида и архитектора коммитятся в `main` отдельными коммитами `docs(...)`. В ветке фазы — только код фазы и её handover.

## 6. Можно ли начинать Ф7a сейчас

**Да.** Ф7a (движок рассадки) зависит только от инструментов Ф0: TypeScript, Vitest, ESLint-правило границ. Аккаунты, база и интерфейс ей не нужны. Переставить её перед Ф2 разумно: Ф2 упирается в Neon и проверку ссылок входа на реальных телефонах, то есть в аккаунты основателя.

Как начать:
- ветка `phase/F7a-seating` от `phase/F0-setup` (в `main` ещё нет каркаса). После мержа Ф0 в `main` — `git rebase main`;
- бриф `docs/phases/Ф7a-brief.md`. Фикстура `tests/fixtures/sample-event.ts` создаётся в Ф7a (Ф2 её потом переиспользует для сидов);
- в handover Ф7a записать отклонение «порядок фаз Ф7a → Ф2 из-за аккаунтов».

Календарь от этого не сдвигается. Ф7a (2,5 дня) занимает время, пока основатель создаёт аккаунты. Ф2 начинается, когда готовы GitHub, Vercel и Neon. Если аккаунты появятся к 16.10, весь план до ворот «Дизайн» идёт с опережением.
