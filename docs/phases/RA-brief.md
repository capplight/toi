# РА · Подготовка релиза A — бриф

Версия 1.0 · 2026-10-12 · архитектор → разработчик (агент) и основатель
Статус: **готов** после правок П1–П2 по Ф6 (`docs/phases/Ф6-review.md`).
Релиз A — «гости и приглашения»: семья-пилот вносит гостей, рассылает приглашения, гости отвечают. Срок по плану — **09.12.2026** (требование — не позже 12.12).
Оценка:
- локальная часть ≈ **4 рабочих дня**;
- часть с аккаунтами ≈ **2–3 дня** после того, как основатель их создаст;
- проверки с людьми — по готовности семьи-пилота.

Ветка: `phase/RA-release-a` от `phase/F6-summary` (после правок).

Связанные документы:
- план v1.9: 4.2 (персональные данные на пилоте), 9 (безопасность, бэкапы), 10 (бюджеты), 11.2–11.3 (окружения, CI/CD), 12.2 (календарь), 14 (чек-лист готовности к пилоту);
- ревью Ф0–Ф6 (дополнения «ждёт аккаунтов»);
- `docs/DECISIONS.md` (Р10, Р11, Р13).

## 2. Часть с аккаунтами (разработчик, после шагов основателя из раздела 3)

1. **GitHub:**
   - push цепочки веток;
   - CI зелёный: unit, integration и e2e на `postgres:16`, в том числе конкурентность Ф4 и `guests-perf` (строгий, `--repeat-each=3`), Docker, gitleaks, Lighthouse CI для `/i/{token}` с бюджетом;
   - мерж по порядку F0 → F7a → F2 → F1 → F4 → F3 → F5 → F6 → RA, каждая ветка — после зелёного CI.
2. **Vercel и Neon:**
   - `ENABLE_EXPERIMENTAL_COREPACK=1` (Н1 ревью Ф0);
   - preview на ветке Neon, где `DATABASE_URL_UNPOOLED` есть при сборке (Н12 ревью Ф2);
   - первый прод через `deploy-prod.yml`;
   - `/api/health` → `ok`, регион `fra1`;
   - Vercel Cron виден, ручной вызов `cleanup` с секретом отвечает 200.
3. **R2:**
   - бакеты и CORS для PUT с домена;
   - драйвер `s3`: загрузка музыки, обработка ffmpeg **на Vercel** (размер и время функции; иначе запасной путь из брифа Ф5 — без перекодирования при файле ≤ 3 МБ).
4. **SMS:** `sms:test` по четырём операторам и двум провайдерам, отчёт; код SMSC статуса `4`; реальный вход по коду на проде.
5. **Sentry:** тестовая ошибка с номером телефона в тексте — номер замаскирован, тела запроса и cookies нет.
6. **Бэкапы:** первый запуск `backup.yml` и **пробное восстановление** в новую ветку Neon с проверкой (план 14).
7. **Реальные телефоны** — недорогой Android и iPhone; результаты в handover РА:
   - ссылка составителя из WhatsApp → вход сохраняется (Ф2), подсказка «как открыть снова» (`auth.install.*`);
   - `location.assign(waUrl)` на iPhone (Ф3);
   - S1: тёплое открытие ≤ 1 с, холодное ≤ 2 с на Android (Ф4 / Ф6);
   - страница гостя: превью ссылки в WhatsApp (Android и iOS), звук по «Ашу» во встроенном браузере WhatsApp на iOS, 3D-конверт или `lite` на недорогом Android (Ф5);
   - пауза тоста при касании (Ф1).
8. **Хозяин пилота:** `pnpm admin:owner-link +7…` с переменными прода, ссылка — основателю для отправки.

## 4. Критерии готовности релиза A

1. Цепочка веток в `main`, CI зелёный на Postgres 16; прод `toi-pilot.vercel.app` поднят через `deploy-prod.yml`; `/api/health` → `ok`.
2. Вход: по ссылке из WhatsApp (Android и iOS) и по SMS-коду (минимум Kcell / Activ и Tele2) работает на проде.
3. Мастер, составители, гости, отправка, страница гостя и ответ проверены на проде на реальных телефонах; превью в WhatsApp с картинкой; звук на iOS.
4. Производительность: страница гостя — Lighthouse mobile ≥ 90 в CI или на preview; S1 — медиана < 1 с в CI и ≤ 1 / 2 с (тёплое / холодное) на недорогом Android.
5. Бэкап снят и **восстановлен**; RUNBOOK написан; cron работает.
6. Проверка с людьми 50+ проведена, критичные замечания исправлены.
7. Решение юриста по Р10 получено и выполнено; есть письменное согласие семьи-пилота.
8. Тексты вычитаны; страницы `/privacy` и `/terms` на месте.
