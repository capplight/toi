## 4. Контракт адаптера `withSeating` (для Ф5 и Ф7b)

```ts
// src/server/seating/adapter.ts
type Actor = { kind: "member" | "system" | "guest"; memberId: string | null };
type SeatingStep<T> = (ctx: { tx: Tx; state: SeatingState }) => Promise<{
  result: SeatingResult;            // результат функции движка над ctx.state
  action: SeatingAction;            // enum seating_action: auto_place | answer | move | unseat | undo | …
  summary: Record<string, unknown>; // для текста истории: names, from, to, reason…
  value: T;                         // что вернуть вызывающему
}>;
type SeatingOutcome<T> = { seatingVersion: number; changes: Delta[]; warnings: Warning[]; historyId?: number; value: T };

function withSeating<T>(db: Db, eventId: string, actor: Actor, step: SeatingStep<T>): Promise<SeatingOutcome<T>>;
function loadSeatingState(tx: Db | Tx, eventId: string): Promise<SeatingState>; // после блокировки
function rowToFamily(row): Family; function familySeatColumns(f: Family): { tableNo; seatLocked; lockedByMemberId };
function historyDiff(before: SeatingState, after: SeatingState): SeatingDiff;
class NotFound extends Error {} // событие удалено / не найдено
```
Правила: шаг сам пишет «не-местные» колонки (rsvp, deleted_at, insert) в `tx`; колонки мест пишет только адаптер по `deltas`; семья, исчезнувшая из состояния (мягкое удаление), сохраняет прежний стол в строке. Зал берётся из `events.hall_columns / tables_count / seats_per_table` (строки `hall_tables` создаёт мастер/настройка зала и нужны для FK). Ф5 (ответ гостя) — `actor {kind:'guest', memberId:null}`, `action:'answer'`, `setRsvp`. Ф7b — `move / unseat / order / hall / full_reseat / undo` тем же способом.

## 8. Отклонения от брифа и макетов

1. **Ссылки wa.me строятся на клиенте**, а не на сервере: тексты `wa.*` приходят в клиентские сообщения один раз (вместо двух длинных закодированных ссылок на каждую карточку в RSC). Дата события форматируется на сервере (`WaEvent.dateText`), иначе ICU Node и браузера давали разный текст и ошибку гидратации. На карточке S1 полный текст подставляется в `href` лениво (pointer-down / focus / hover / click — всегда до перехода); до этого `href` = `https://wa.me/<номер>` (чат без текста). Причина — критерий 6.
2. **Первые 8 карточек** рендерятся сразу (SSR и гидратация), остальные — когда браузер свободен (`requestIdleCallback`, не позже 600 мс, низкоприоритетный переход). На телефоне они ниже первого экрана; поиск и фильтр сразу работают по всему списку. Для групп вне экрана — `content-visibility: auto`.
3. **Окно S2-ok и «Бұл сол адам ба?»** — `Dialog` кита (на телефоне — шторка снизу, на десктопе — по центру), как и в макете. Переход после закрытия ждёт `history.back()` шторки (`afterSheetClosed`), иначе «Назад» шторки отменял переход.
4. **Мини-конверт** в правой колонке S2 (`.mini-env` макета) не перенесён — только две подсказки `guestForm.aside.*`. Это декоративная превью-карточка; удобнее сделать вместе с шаблонами приглашений (Ф5).
5. **«Санат қосу»** — отдельная пунктирная плитка под сеткой (как в Ф1 `CategoryTiles`), а не девятая плитка сетки.
6. **«Қонақ сақталмайды. Шығасыз ба?»** перехватывает переходы по ссылкам внутри приложения и закрытие вкладки (`beforeunload`); системный жест «Назад» Android без шторки не перехватывается (Next не даёт отменить popstate).
7. **«Басқа тізімдер» на телефоне** показаны после списка (в макете только на десктопе; бриф: «на десктопе — правая колонка»). Список другого составителя — тот же экран с его именем в заголовке; добавление из него идёт в свой список.
8. **Ответ «Келмейді» по телефону** — тост с «Қайтару» (`revertAnswer` через движок): design_spec 4.7 это предлагает, в брифе не было.
9. **Счётчик «Жауап жоқ»** на S1 = только отправленные без ответа (design_spec 4.1, макет: 4); «Жіберілмеген» не входит. По А4 они входят в сводные числа Ф6 — для этого `listTotals().notSent`.
10. **Локальный e2e — последовательно** (`--workers=1`): PGlite держит одно соединение, параллельные транзакции двух проектов давали ошибки сохранения и «выход» сессии. В CI с настоящим Postgres работает параллельно. По той же причине integration-тест «два одновременных `addFamily`» на PGlite выполняется по очереди; блокировку `for update` реально проверит CI на Postgres.
11. Тест B1 из Ф1 (`ui.spec.ts`) — ждёт 600 мс окончания анимации тоста: при полном последовательном прогоне один раз измерил тост на середине въезда.
