## 1. Цель

Перенести утверждённый дизайн v2.2 в код:
- **токены** (Tailwind v4 `@theme`);
- **библиотека компонентов** со всеми состояниями на `/dev/ui`;
- **каркас рабочих экранов** в трёх режимах навигации;
- **графика стола и SVG-зала**;
- **временные экраны `/join` и `/login`**, перекрашенные по макету 09.

После Ф1 экранные фазы (Ф3, Ф4, Ф6, Ф7b, Ф8) собирают экраны из готовых деталей и не изобретают стили.

**Не входит в Ф1:**
- страница гостя и конверт — Ф5: там своя технология, обычный HTML без React (план 10);
- PWA помощника — Ф8;
- реальные данные на экранах. Компоненты получают данные через props; на `/dev/ui` — демо-данные из `tests/fixtures/sample-event.ts`;
- Motion (`motion/react`) — подключается в Ф7b для перестановок H5, если CSS не хватит.

## 2. Решения (не обсуждаются в фазе)

| Тема | Решение |
|---|---|
| Токены | Источник — `design/v2/mockups/css/tokens.css`. Переносятся в `src/ui/tokens.css` как CSS-переменные + Tailwind v4 `@theme`. Имена совпадают с дизайном (`--lapis`, `--ink-2`, `--cat-kuda`, `--seat-taken` …). В компонентах — только токены, без «магических» цветов и размеров |
| Шрифты | `next/font/local` из **копий** woff2-подмножеств: `design/v2/assets/fonts/{onest-400-kk,onest-600-kk,cormorant-garamond-600-kk}.woff2` → `src/ui/fonts/`. Cormorant только от 20 px. Google Fonts не используем |
| Ассеты | Иконки (`icons.svg`), орнаменты, знак «Той» **копируются** из `design/v2/assets/` в приложение: `public/` или `src/ui/…` как React-компоненты. Прямые импорты из `design/` запрещены: `design/` нет в Docker-образе |
| Компоненты | Стиль shadcn/ui: код в `src/ui/components/`, Radix-примитивы, **Vaul** (шторки), **Sonner** (тосты), `class-variance-authority` для вариантов. Список — DESIGN_v2 раздел 7 |
| Тексты | Только из `content/messages`; при расхождении с макетом побеждают `content/messages` (А5). Ключей не добавлять. Если строки не хватает — записать в handover как запрос контент-лиду |
| Язык | Видимый «ҚАЗ \| РУС» — только на `/join` и `/login` в этой фазе (страница гостя — Ф5). На рабочих экранах язык меняется в «⋯ Той мәзірі» (Д3) |
| Пометка «тестовая версия» | Компонент `PilotBanner` (`legal.pilotBanner`), показывается только при `role = owner` (prop). Подключение к роли — в каркасе `/e/[eventId]` (роль уже есть в Ф2) |

## 3. Задачи

### 3.1 Основа
- [ ] `src/ui/tokens.css`:
  - цвета 3.1 и оттенки категорий 3.2;
  - состояния стульев 3.3;
  - типографическая шкала 3.4;
  - отступы, радиусы, тени, высоты 3.5;
  - кривые движения из раздела 6;
  - `prefers-reduced-motion` глобально: без `transform`, только прозрачность ≤ 250 мс.
- [ ] Подключение шрифтов (`next/font/local`); `font-variant-numeric: tabular-nums` для чисел.
- [ ] Спрайт иконок + компонент `Icon` (подпись рядом обязательна, `aria-hidden` у SVG). SVG-орнаменты как компоненты с анимацией «рисования» (`pathLength=1`, `stroke-dashoffset`).

### 3.2 Компоненты (все состояния из DESIGN_v2 раздел 7)
- [ ] **Действия:** Button (все варианты и состояния), LanguageSwitch (только `/join`, `/login`), EventMenu «⋯», Segment «Схема \| Тізім».
- [ ] **Навигация:** Tabs (3 нижние вкладки), Rail (104 px), Sidebar (272 px).
- [ ] **Ввод:** CategoryTiles, Stepper (64×64, 1–20), Input / PhoneInput (+7, ошибки рядом с полем, `aria-invalid` и `aria-describedby`), Search.
- [ ] **Списки и статусы:** GuestCard (мобильная и десктопная строка, все статусы, `flash`, строка «Шақыруды WhatsApp-та жібердіңіз бе?»), StatusBadge, CounterTile, Banner, **StatusChip**, **SummaryLine**, EventHero (компактный режим — N1 ревью дизайна), LinkRow, Accordion, ProgressBar.
- [ ] **Оверлеи:**
  - **Sheet** (Vaul: снизу на телефоне, `direction="right"` 480 px на ≥ 1024);
  - **Dialog / AlertDialog** (центр на ≥ 1024, на телефоне — Vaul);
  - системная кнопка «Назад» закрывает шторку.
- [ ] **Toast** (Sonner) по правилу B1:
  - одна строка ≤ 56 px, длинное имя обрезается многоточием;
  - тост стоит над вкладками или главной кнопкой;
  - пока тост виден, у прокручиваемой области есть нижний отступ на его высоту;
  - одновременно только один тост;
  - 8 с, «Қайтару», пауза при касании.
- [ ] `PilotBanner` (только хозяину).

### 3.3 Графика зала
- [ ] **TableGraphic** в трёх размерах по `design_spec` 3.12 (ячейка 82×86, ячейка 164×140, крупная 200×200 с номерами семей). Состояния 3.3: занят / свободен / пустой (пунктир) / переполнен (кольцо + «!») / дубль / кандидат / текущий / выбранный.
- [ ] **HallMap** — одна SVG по геометрии 3.13 и DESIGN_v2 раздел 9:
  - ТӨР, стол молодых или «Құрметті үстел» (`hall.map.coupleTable` с `{kind}`), КІРЕБЕРІС;
  - 2 и 4 колонны; неполный последний уровень;
  - нажатие на ячейку стола: `role="button"`, `aria-label` = `hall.map.tableA11y` с `{missing}`; стулья `aria-hidden`;
  - **данные — из `@/domain/seating` `tableStats`** (контракт Ф7a). Компонент ничего не считает сам.
- [ ] Проверка: 20 столов × 16 мест в 4 колоннах помещаются в 328 px; на 1440 схема вписана по высоте вместе с легендой.

### 3.4 Каркас экранов
- [ ] Каркас `/e/[eventId]` в трёх режимах (DESIGN_v2 раздел 4):
  - **до 767 px:** шапка 60 с «⋯», 3 нижние вкладки (Қонақтар · Зал · Қорытынды), «Шығындар» — карточка на «Қорытынды», только при `can_manage_budget`;
  - **768–1279:** рейка;
  - **от 1280:** боковая панель;
  - две колонки от 1024.

  Вкладки ведут на пустые страницы-заглушки с заголовками из `content/messages`.
- [ ] Перекрасить `/join` (все состояния: обычный, «Сілтеме жарамсыз») и `/login` (телефон, код, «Код келмеді ме?») по макету 09. Логика Ф2 не меняется.
- [ ] `/e`: список тоев в новых стилях (простой).

### 3.5 Витрина и проверки
- [ ] `/dev/ui`: каждый компонент во всех состояниях, kk и ru, переключатель «reduced motion» для проверки. **Отдаёт 404 на продакшене** (`VERCEL_ENV === "production"` или своя проверка окружения).
- [ ] Playwright (360×740, 320×640, 1440×900):
  - скриншоты ключевых страниц `/dev/ui` и каркаса — для handover, **не** как сравнение с эталоном: шрифты на Windows и в Linux-CI рендерятся по-разному;
  - **проверки доступности `@axe-core/playwright`** — без нарушений уровня serious / critical;
  - нет горизонтальной прокрутки (`scrollWidth ≤ innerWidth`);
  - цели нажатия ≥ 48 px у интерактивных элементов `/dev/ui` (скрипт по `getBoundingClientRect`, исключения — только метки схемы, они не кнопки);
  - системный шрифт 130 % (`page.setViewportSize` + `html { font-size: 130% }`) — без поломок раскладки.
- [ ] Сценарий из ревью дизайна (критерий B1) на демо-данных: экран-образец «Зал» на 360×740 с чипами переполнения, дублей и неразмещённых и с тостом — «ТӨР» и первый уровень столов видны без прокрутки.

## 4. Критерии приёмки

1. Токены, шрифты и ассеты — только из копий дизайна в приложении. Цветов и размеров вне токенов в `src/ui` нет (проверка grep на `#[0-9a-f]{3,6}` вне `tokens.css`).
2. Все компоненты раздела 7 (кроме Envelope, RSVP, MusicToggle, MiniHallMap, OfflineIndicator — это Ф5 и Ф8) есть на `/dev/ui` во всех состояниях, на kk и ru.
3. Каркас работает в трёх режимах навигации. «Шығындар» скрыт без права. Язык на рабочих экранах — только через «⋯».
4. HallMap рисует сид-событие (16 столов) и 20 × 16 по `tableStats`. Состояния переполнения, дублей и кандидатов совпадают со скриншотами дизайна. aria-метки из `content/messages`.
5. Toast по правилу B1; критерий B1 выполнен на демо-экране «Зал» (360×740 и 320×640).
6. axe без serious / critical; цели ≥ 48 px; нет горизонтальной прокрутки на 320, 360, 768, 1024, 1440; reduced motion отключает движение.
7. `/join` и `/login` в новом стиле; e2e Ф2 зелёные (селекторы по ролям и текстам, не по классам).
8. `/dev/ui` недоступен на продакшене.
9. `typecheck`, `lint`, unit, integration, e2e, `check:messages` — зелёные.

## 5. Пакет сдачи (`docs/phases/Ф1-handover.md`, план 13.5)

Общая часть — плюс:
- **скриншоты** `/dev/ui` и каркаса **рядом с соответствующими скриншотами дизайна** (360 и 1440, kk и ru, 130 %);
- отчёт axe;
- список компонентов с путями файлов и props (это контракт для Ф3–Ф8);
- новые зависимости с обоснованием (ожидаются: Radix-примитивы, `vaul`, `sonner`, `class-variance-authority`, `clsx`/`tailwind-merge`, `@axe-core/playwright`);
- расхождения с макетами и почему (например, текст из `content/messages` длиннее макета);
- запросы контент-лиду, если не хватило строк.

## 6. Акценты ревью

- Соответствие макетам и токенам: не «похоже», а те же токены и размеры.
- Доступность: фокус в шторках, «Назад», aria на SVG.
- Правило B1 на реальных длинах текстов.
- HallMap ничего не вычисляет сам — только `@/domain/seating`.
- Импортов из `design/` нет.
- Никакой бизнес-логики и обращений к базе в `src/ui`.
