## 1. Исходное состояние (замер 2026-10-27, выкладка 984c188)

- `/kk`: 8 внешних скриптов. Сумма gzip **≈ 233 КБ**, из них `noModule`-полифиллы ≈ 39 КБ (современный браузер их не качает) → **реальный стартовый JS ≈ 193 КБ gzip** (≈ 200 КБ brotli при передаче). Совпадает с handover (≈ 190).
- Sentry сидит в самом большом чанке (395 КБ raw / 128 КБ gzip, вместе с React DOM); по грубому разбиению на модули — **≈ 55–75 КБ gzip**. Других модулей приложения (next-intl, zod, `src/ui`) в чанках сайта не нашлось. Остров сайта ≈ 2 КБ.
- Вывод: после удаления Sentry ожидается **≈ 120–140 КБ gzip**. Цель SEO_PLAN 5.7 (≤ 90 КБ) на App Router с React недостижима: это пол фреймворка (React DOM + роутер Next). Настоящий критерий скорости — Lighthouse mobile ≥ 90 (SEO-12). SEO-менеджер после замера инженера правит SEO_PLAN 5.7 (см. 8.3).
- `/i/{token}` — строка HTML из route handler без React и без браузерного Sentry; мониторинг гостевой страницы — серверный (`instrumentation.ts › onRequestError`), он не меняется.
- Неизвестные `BLOCK`-маркеры парсер молча пропускает (`parse.ts`, ветка `default`).
- `DemoInvite` (превью на T3) всегда пишет «Үйлену тойы · Айбек пен Дана», даже на `/kk/shaqyru/sundet-toi` и `/mereitoi`.

## 2. П1 · Убрать Sentry и лишний JS со страниц сайта

### Цель
На `/kk/**` и `/ru/**` не загружается ни байта Sentry; в приложении (`/e/**`, `/login`, `/join`, `/d/**`, `/dev/**`) браузерный Sentry работает как сейчас, если задан `NEXT_PUBLIC_SENTRY_DSN`.

### Решение
`instrumentation-client.ts` выполняется на **всех** страницах при любом корневом layout (docs: `03-file-conventions/instrumentation-client.md`); статический `import * as Sentry` поэтому попадает в общий бандл. Делаем так:

```ts
// src/instrumentation-client.ts — схема, не готовый код
const dsn = process.env.NEXT_PUBLIC_SENTRY_DSN;      // подставляется при сборке
if (dsn && !isSitePath(location.pathname)) {
  void import("./sentry.client").then((m) => m.init(dsn));   // отдельный ленивый чанк
}
```

- `src/sentry.client.ts` (новый) — бывшее содержимое: `Sentry.init({ dsn, dataCollection: strictDataCollection, tracesSampleRate: 0, beforeSend: scrubEvent })`.
- `isSitePath` — чистая функция (например, `src/site/paths.ts`, без импортов `next`/`react`): `true` для `/kk`, `/kk/…`, `/ru`, `/ru/…`; `false` для `/kkx`, `/e`, `/login`, `/i/…`, `/`. Переход между корневыми layout-ами (сайт ↔ приложение) — всегда полная загрузка страницы, поэтому проверки пути при старте достаточно.
- Без DSN ветка выкидывается минификатором целиком — чанка Sentry нет вообще.
- `onRouterTransitionStart` **удалить**: при `tracesSampleRate: 0` он ничего не даёт. Отметить в «Отклонениях» handover.
- `instrumentation.ts`, `sentry.server.config.ts`, `sentry.scrub.ts`, `withSentryConfig` в `next.config.ts` — **не трогать** (сервер и source maps).
- Известная цена: ошибки, случившиеся в приложении до загрузки ленивого чанка (первые десятки мс), не попадут в Sentry. Для пилота приемлемо; записать в handover.

Альтернативы (отклонены): (а) `instrumentationClientInject` (Next ≥ 16.3) — тоже глобален, проблему не решает; (б) инициализация из клиентского компонента в `(app)/layout.tsx` — теряем ошибки гидратации и добавляем клиентский компонент в приложение; (в) CDN-лоадер Sentry — внешний скрипт и CSP; (г) отказ от React на сайте (HTML из route handlers, как `/i`) — переписывание фазы 1, только если Lighthouse < 90 после П1 (вопрос основателю, не в этой фазе).

### Файлы
`src/instrumentation-client.ts`, `src/sentry.client.ts` (новый), `src/site/paths.ts` (новый), `tests/unit/site-paths.test.ts` (новый), `tests/e2e/site-budget.spec.ts` (новый).

### Бюджеты (обязательные)
Метод: e2e-тест против собранного standalone-сервера берёт HTML страницы, все `<script src>` **без** `nomodule`, скачивает файлы, сжимает в Node `zlib.gzipSync(buf, { level: 9 })`, суммирует. Inline-скрипты RSC (`self.__next_f`) считаются весом HTML, не JS.

| Что | Бюджет | Страницы |
|---|---|---|
| Признаки Sentry в JS (`__SENTRY__`, `sentry_key`, `@sentry/`) | **0** | `/kk`, `/ru`, `/kk/tilekter/sundet-toi`, `/kk/dastur/betashar`, `/ru/rassadka-gostei`, `/kk/shaqyru/ulgi/ak-shanyraq` |
| Стартовый JS страницы сайта | **≤ 140 КБ gzip** (жёстко); фактическое значение и разбивка по чанкам — в handover | те же |
| Остров сайта (`SiteIsland`) | ≤ 5 КБ gzip | — |
| Демо-страница `…/demo` (П4) | 0 внешних скриптов; встроенный скрипт ≤ 3 КБ gzip | 3 + 3 демо |
| HTML `/kk`, `/ru` после П6 | рост gzip ≤ 15 % к замеру до фазы | — |

Тест должен **падать на `main` до правки** (признак Sentry есть) — показать в handover красный и зелёный прогон.

### Приёмка
1. Бюджеты выше зелёные в `pnpm test:e2e`.
2. Отдельная локальная сборка с фиктивным `NEXT_PUBLIC_SENTRY_DSN=https://public@o0.ingest.invalid/0`: на `/login` и `/e` грузится ленивый чанк Sentry и есть `window.__SENTRY__`; на `/kk` — нет ни запроса, ни глобала. Вывод — в handover (запросы к `*.invalid` в этом прогоне блокировать через `page.route`).
3. `pnpm typecheck`, `lint`, `test`, `check:messages`, `build` зелёные; e2e приложения не сломаны (`smoke`, `auth`, `invite`, `ui`).

### Риски
- Плагин Sentry для Turbopack может вставлять код во все клиентские бандлы. Проверка — тот же скан признаков. Если признак остаётся без статического импорта — остановиться и написать архитектору, не отключать `withSentryConfig`.
- Динамический `import()` в `instrumentation-client` под Turbopack должен дать отдельный чанк — проверить в `.next/static/chunks` и в Network.

## 3. П2 · «Деректер әртүрлі», словарь терминов, цитаты

### Цель
Компоненты SITE_DESIGN §4.5, §4.10 и цитата получают маркеры в контенте и рендерятся на сайте. Смысл текста не меняется.

### Синтаксис маркеров (одинаковый для kk и ru; закрывающий маркер обязателен в обоих языках)

**1. Расхождение источников — `differ`**
```md
<!-- BLOCK: differ topic="Тұсауды кім кеседі" -->
- **Бір деректе:** көбіне көп балалы, тәжірибелі әйел кеседі. <!-- S9 -->
- **Басқа деректе:** ер адам да кесе береді. <!-- S10 -->

Яғни нақты ереже жоқ.
<!-- /BLOCK -->
```
- 2 пункта (максимум 3). Каждый начинается с **жирной подписи-атрибуции с двоеточием** — она идёт в строку `.who` («Қазақстандық деректерде:», «ЮНЕСКО сипаттамасында:», «Этнолог М. Егизбаева:», ru: «По одному источнику:», «Этнограф Н. Байгабатова:»). Буквы А/Ә (ru А/Б) рисует компонент.
- Метки `<!-- S# -->` остаются на месте, внутри пунктов.
- Абзац после списка — необязательный вывод (`.differ-foot`).
- `topic` — необязателен (подзаголовок блока, не H-заголовок).
- Когда ставить: в research или в тексте **две атрибутированные версии из разных источников** (⚠, «деректер әртүрлі», «источники расходятся», «этнологи расходятся во мнениях»). **Не ставить**: «әр отбасы өзі шешеді», различия цен, региональные варианты без противоречия.

**2. Слова из статьи — `terms`**
```md
<!-- BLOCK: terms korimdik shashu -->
<!-- /BLOCK -->
```
- 2–4 якоря разделов `/kk/dastur/toi-sozdigi` (`{#asaba}`, `{#nagashy}`, `{#tor}`, `{#kiit}`, `{#quda}`, `{#qalyn-mal}`, `{#ana-suti}` …). Определение **не пишется** в статье: компонент берёт **первое предложение** раздела словаря (без `S#`). Один источник правды — словарь.
- Сборка падает, если якоря нет в `dastur-toi-sozdigi.md`.
- **Гейт:** блок рендерится, только если страница словаря **опубликована** (сейчас `needs_fix` + `needs_tradition_review` → блоки не видны). Иначе непроверенные определения обошли бы гейт.
- **Только kk.** ru-словаря нет; ru-страницы блок не получают (существующий «словарик» в `ru/dastur-qudalyq.md` остаётся текстом).

**3. Цитата — `quote`**
```md
<!-- BLOCK: quote cite="Этнограф С. Кенжеахметұлы, «Жеті қазына»" -->
> «Жаңа түскен келінді беташар дәстүрі жасалмай ешкім көре алмайды» <!-- S4 -->
<!-- /BLOCK -->
```
- **Только дословные цитаты**, которые в research стоят в кавычках с источником. Пересказ («…айтуынша, …») в цитату **не превращать**: это меняет утверждение (пересказ становится «прямой речью»). Редактор сверяет каждую цитату с research дословно.
- Пословицы — по-прежнему `<!-- folk -->`, не `quote`.

### Где ставить (кандидаты; редактор подтверждает по research)
| Маркер | kk | ru |
|---|---|---|
| `differ` | `dastur-tusaukeser` (кто режет; нож/ножницы), `dastur-sundet-toi` (возраст; «трон»), `dastur-syrga-salu` (время обряда), `dastur-shildekhana` (сроки), `dastur-betashar` (кто открывает лицо: ЮНЕСКО / казахстанские источники — как в макете), `tilek-bata` и `tilekter-hub` (женщина и бата — один блок на странице) | `dastur-tusaukeser`, `dastur-sundet-toi`, `dastur-syrga-salu` (время; материал серёг), `dastur-qyz-uzatu` (жених на ұзату) |
| `terms` | `dastur-betashar` (көрімдік, шашу), `dastur-qudalyq` (киіт, quda), `dastur-qyz-uzatu` (qalyn-mal, ana-suti), `dastur-besik-toi` (nagashy), `dastur-uilenu-toi` (asaba), `rassadka` (tor) — только якоря, которые есть в словаре | — |
| `quote` | где в research есть дословная цитата (пример — `dastur-betashar`, Кенжеахметұлы) | `dastur-sundet-toi` («Этот обряд совершенно несвойственен для казахов», S31 — уже отмечено в `ru/_EDITOR_REVIEW.md` как атрибутированная цитата) |

Не более 2 `differ`, 1 `terms`, 2 `quote` на страницу.

### Кто и как
1. **Редактор kk** и **редактор ru** — один проход по своим страницам. Разрешено: обернуть текст маркерами; разбить фразу на два пункта; вынести атрибуцию в жирную подпись; убрать связки («ал», «однако», «по другому»). Запрещено: новые факты, смена степени уверенности (✓ → утвердительно), удаление или перенос `S#` в другой пункт, смена `status`.
2. Каждая правка — строка в `content/site/{kk,ru}/_EDITOR_REVIEW.md`, раздел «Маркеры фазы 2» (страница, маркер, что изменено в словах).
3. **SEO-менеджер** проверяет: число меток `<!-- S` на каждой странице до и после одинаково; ключи и H2 не тронуты. Коммит в `main`: `docs(content): маркеры differ/terms/quote`.
4. Подписи интерфейса («Деректер әртүрлі», А/Ә, «Мақаладағы сөздер», «Той сөздігі») — ключи `site.*` (раздел 9), не контент.

### Рендер (инженер)
- `parse.ts`: узлы `{ t: "differ", topic?, items: {who, c}[], foot? }`, `{ t: "terms", ids: string[] }`, `{ t: "quote", cite, c }`. Для этих трёх `/BLOCK` обязателен — нет закрытия → ошибка сборки с именем файла и строкой.
- **Список известных имён блоков**: неизвестное имя → ошибка сборки (сейчас молча пропускается). Сначала собрать все имена из текущего контента и убедиться, что их 0 неизвестных.
- `blocks.tsx`: `differ` → разметка из макета `design/v2/site/kk-dastur-betashar.html` (`aside.differ` с `aria-label`, `.differ-head` со значком `i-split`, `.differ-v .who b`, метки — `<p>`, не заголовки); `terms` → `aside.glossary` + `<dl>`, термин — ссылка на `/kk/dastur/toi-sozdigi#id`, «Той сөздігі →»; `quote` → `<figure><blockquote>…</blockquote><figcaption>— <cite>…</cite></figcaption></figure>`.
- FAQPage JSON-LD и текст для `nodesText` — без подписей компонентов.
- CSS уже в `src/site/site.css` (`.differ*`, `.glossary`, `.prose blockquote`) — новых стилей минимум.

### Приёмка и тесты
- `tests/unit/site-parse.test.ts`: каждый маркер разбирается (kk и ru); нет `/BLOCK` → ошибка; неизвестный блок → ошибка; `terms` с несуществующим якорем → ошибка; `terms` при неопубликованном словаре → узел не выводится; `S#` в пунктах не теряются.
- e2e: страница с `differ` и `quote` (после маркеров — `/kk/dastur/tusaukeser` или другая, где они реально есть) — блоки видны, в HTML нет текста `BLOCK`, axe без serious/critical, 320/360 без горизонтального скролла; `differ` на 360 — версии друг под другом, на 1440 — рядом.
- Публикация не изменилась: число опубликованных страниц до/после = то же (+ besik по П5).

### Риски
- Редактор «улучшит» текст при оборачивании → контроль по `_EDITOR_REVIEW.md` и `git diff --word-diff`.
- Маркеры в неопубликованных страницах (большинство дәстүр) не видны до подписи О8 — это нормально; проверять рендер на `alwaysPublish` только локально, не коммитить.

## 4. П3 · Картинки превью ссылок (OG/Twitter)

### Цель
У каждой страницы сайта своя картинка 1200×630 для WhatsApp, Telegram, Facebook, X; язык картинки = язык страницы; бренд из `SITE_CONFIG`.

### Решение
- **Маршрут:** `src/app/og/[locale]/[[...slug]]/route.tsx` — обычный route handler с `ImageResponse` из `next/og` (не `@vercel/og`), `runtime = "nodejs"`, `dynamic = "force-static"`, `dynamicParams = false`, `generateStaticParams` из `allPages()`. Картинки строятся **при сборке**: `content/site` в рантайме недоступен (`outputFileTracingExcludes`), а шрифты нужны только сборке.
- Почему не `opengraph-image.tsx` внутри `(site)/kk/[[...slug]]`: файл-метаданные в группе маршрутов получает суффикс-хеш (см. 984c188 с `/i`), alt один на файл (нужен `generateImageMetadata`), а optional catch-all с файлом-метаданными — лишний риск. Явный маршрут даёт стабильный URL `/og/kk/tilekter/sundet-toi`.
- **Метаданные** (`src/site/seo.ts › pageMeta`): `openGraph.images = [{ url: absolute("/og/…?v=<8 знаков хеша h1+шаблона+бренда>"), width: 1200, height: 630, alt }]`, `twitter: { card: "summary_large_image" }`. `?v=` — сброс кэша мессенджеров при смене заголовка/бренда.
- Попутно (замечание к фазе 1): `og:locale` для ru — `ru_RU` (в OG нет `ru_KZ`, SEO_PLAN 5.5), у пар — `og:locale:alternate`.
- **Шаблоны** (эскиз — дизайнер, 1 лист PNG/HTML 1200×630 на шаблон, токены `DESIGN_v2`):

| Шаблон | Страницы | Содержимое |
|---|---|---|
| `landing` | T1 | знак шаңырақ + `BRAND`, H1 (Cormorant 600), строка доверия из `site.trust.*` |

## 5. П4 · Экран «Рақмет» в демо-приглашении

### Цель
Посетитель сайта в демо (`/kk/shaqyru/ulgi/{slug}/demo`, `/ru/priglashenie/shablon/{slug}/demo`, в т. ч. в iframe на T4) отвечает «Келеміз»/«Келе алмаймыз» и видит, что увидит гость, — без базы и без сети.

### Решение
- `renderInvite(page, o)` получает **новый режим** `o.demo?: { thanksNote: string; cta: { text: string; href: string } }`. `preview` (мастер и настройки) **не меняется**.
- В режиме `demo`:
  - форма как у гостя, но `action="#rsvp"`, кнопка **активна**; без JS — кнопка `disabled` (сейчас так и есть), скрипт её включает;
  - в HTML заранее отрендерены две карточки «answered» в `<template>`: «Рақмет! Сізді күтеміз» + «Келеміз · {N} орын» и «Хабарлағаныңызға рақмет!» (те же ключи `invite.thanks.*`), под ними плашка `site.demo.thanks.note` («Бұл — демо: жауап ешқайда жіберілмеді») и кнопка `site.demo.thanks.cta` → `/login?next=/e/new` (как CTA страницы) с `target="_top"` (страница в iframe);
  - «Жауапты өзгерту» возвращает форму (в демо — кнопка, а не ссылка на `/i/demo?change=1`);
  - после «Келеміз» — блок «Сіздің үстеліңіз» с вымышленным номером 7 без схемы зала (`page.table = { tableNo: 7, hall: null, doorOpened: false }`) и подписью `site.demo.thanks.table` («Той жақындағанда үстел нөмірі осында шығады»);
  - встроенный скрипт `DEMO_ISLAND_JS` (≤ 3 КБ gzip): степпер мест, скрытие мест при «Келе алмаймыз», подмена формы на карточку, фокус на заголовок карточки (`tabindex="-1"`), `aria-live` не нужен — фокус достаточно. **Нет** `fetch`, `sendBeacon`, cookie, `ISLAND_JS` гостя в демо не подключается. Конверт/музыку не трогаем (в демо они скрыты, как сейчас).
- `src/site/demo.ts` передаёт `demo: {…}` вместо `preview: true`; в ответе нет `data-token` реального вида и нет ссылок на `/i/`, `/api/`.

Альтернативы: отдельные статические страницы `…/demo/rahmet` (без JS, но нельзя показать выбранное число мест и два исхода без двух URL); «понарошку» POST в route handler (лишний серверный код и риск записи) — отклонены.

### Файлы
`src/server/invite/render.ts`, `src/server/invite/island.ts` (+ `DEMO_ISLAND_JS`), `src/site/demo.ts`, `tests/unit/invite.test.ts`, `tests/e2e/site.spec.ts`.

### Приёмка и тесты
- **Гостевая страница не изменилась:** unit-тест сравнивает HTML `renderInvite` для фикстуры без `demo` (режимы form / answered / closed и `preview`) с эталоном до правки (снимок или хеш) — байт в байт.
- unit: демо-HTML не содержит `/api/`, `/i/`, `sendBeacon`, `fetch(`; содержит `<template>` обеих карточек.
- e2e (360 и 1440, kk и ru): «Келеміз» → 3 места → «Жіберу» → карточка «Рақмет» с «3 орын», номер 7, плашка демо; «Жауапты өзгерту» → форма; «Келе алмаймыз» → своя карточка. `page.on("request")` за всё время: ни одного POST, ни одного запроса к `/api/` и `/i/`. axe без serious/critical; 320/360 без горизонтального скролла; в iframe на T4 CTA открывает верхнее окно.

### Риски
Правка общего рендерера гостевой страницы — самая опасная в фазе: только аддитивный код за флагом `demo`, эталонный тест обязателен; e2e `invite.spec.ts`, `invite-small.spec.ts`, `music.spec.ts` прогнать полностью.
