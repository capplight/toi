## 1. Цель

Хозяин и составители печатают план рассадки для ресторана, для помощника на входе и на случай, если сайт недоступен. Они же скачивают Excel со списком гостей по столам.

## 2. Печать — `/e/[eventId]/print/tables`

Страница для печати (`requireMember`), A4 книжная, `@page { size: A4; margin: 12–14mm }`, `break-inside: avoid` для блоков, нумерация страниц `print.pageOf` там, где поддерживается (иначе — номер в подвале каждой секции). На экране кнопка `print.button` → `window.print()`. Серверный PDF не делаем: на Vercel нет браузера, а «Сохранить как PDF» есть в любом телефоне и ПК.

Структура — **по образцу основателя:**
1. **Шапка** `print.header` (название, дата, ресторан) + `print.generatedAt`.
2. **Страница схемы зала:**
   - печатный вариант `HallMap`: те же 2 / 4 колонны и стол молодых («ТӨР»); схема вписана в высоту страницы;
   - стулья окрашены **по категории семьи** — цвета категорий из токенов, как в образце;
   - номер стола и «занято / мест»; столы, где сидят **разные категории**, помечены `print.mixed` («аралас үстел»);
   - легенда категорий с цветом **и подписью** (цвет — не единственный признак, печать бывает чёрно-белой).
3. **По столам:** для каждого стола — номер, `print.table.total`, основная категория, список семей (`print.table.colFamily`, `colSeats`, пустая колонка `colArrived` с квадратом для отметки ручкой). Ожидаемые (без ответа) — с «~» и пометкой. Отказавшиеся не печатаются. По 2–3 стола на страницу, без разрыва блока.
4. **По группам (категориям):** категория → столы, где она сидит (диапазон, как в H5) → семьи и места. Это раздел «Топтар бойынша» из образца.
5. **По алфавиту** (`print.alpha.title`): «Аты → үстел» — бумажная копия для помощника на входе.
6. **Без места:** «Отырғызылмағандар», если такие есть.

Все числа — из `tableStats` и `totals` движка. Ссылка на печать — на экране «Зал» (H2, ссылки) и на «Қорытынды».

## 3. Excel — `GET /e/[eventId]/export/tables.xlsx`

- `requireMember`; `exceljs`. Имя файла: латиница из названия + дата (`toi-aibek-dana-2026-11-15.xlsx`).
- **Листы:**
  - «Үстелдер» (`export.sheets.tables`): стол, отбасы, орын, санаты, жауабы, кімнің тізімі;
  - «Қонақтар» (`export.sheets.guests`): по алфавиту, те же колонны;
  - «Санаттар» (новый ключ): категория, семьи, места, столы.
- Заголовки из `export.columns.*` на языке интерфейса. Строка заголовка закреплена, ширина колонн по содержимому, числа — числами.
- **Без телефонов** (минимизация данных: файл уходит в ресторан).
- `activity_log` → `export`.

## 5. Тесты и приёмка

- **unit:** сборка данных печати и листов Excel на фикстуре `design_spec` 5.2 (столы, «аралас үстел», алфавит, без места); форматтеры.
- **integration:** 403 чужому (печать и xlsx); xlsx читается `exceljs`, строк = рассаженных и ожидаемых семей, телефонов нет.
- **e2e:**
  - `page.emulateMedia({media: 'print'})` → нет горизонтальной прокрутки на A4, легенда на месте;
  - `page.pdf()` (Chromium) → PDF создаётся, в нём есть номера столов и «Аты → үстел»;
  - скачивание xlsx;
  - kk и ru.
- **Приёмка:**
  1. Файл открывается в Excel и Google Sheets, казахские буквы на месте.
  2. PDF из браузера читаем и чёрно-белым.
  3. Вид и состав печати соответствуют образцу основателя (схема с окраской по группам, по столам, по группам, «аралас үстел»).
  4. Даты и суммы во всём приложении идут через общий модуль.

## 7. Открытый вопрос для основателя (после пилота, не в Ф10)

В образце у столов **разное число стульев** (11, 13). В продукте вместимость сейчас одна на весь зал (`seats_per_table`; в `hall_tables.capacity` она хранится по столам, но интерфейса правки нет, и движок считает от общей). Реальные залы бывают такими, поэтому стоит сделать правку числа стульев у отдельного стола в шторке H3 (движок: `layoutTables` с вместимостью по столам). Предлагаю как задачу после Ф10 — решение основателя.
