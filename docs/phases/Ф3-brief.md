## 1. Цель

Хозяин сам создаёт событие и приглашает составителей. Составители входят по ссылке из WhatsApp. После Ф3 семья-пилот может начать работу без скриптов основателя (кроме выдачи первой ссылки хозяину, поток 4).

## 2. Решения по макетам (проверка дизайна архитектором)

Макеты реализуемы и согласуются с планом 6.1 / 6.2 и правилами области доступа сессии. Уточнения для реализации:

| Тема | Решение |
|---|---|
| **Шаг «Зал» в мастере (7 / 8)** | **Принят в Ф3, необязательный** («Кейін баптаймын»). На этом шаге движок `setupHall` вызывается через адаптер `withSeating` уже после создания события; гостей ещё нет. Компонент формы зала — общий с экраном H1 «Залды баптау» в Ф7b. Без зала событие создаётся, зал настраивается позже |
| Черновик мастера | **Не сохраняем.** Состояние шагов живёт на клиенте; «←» спрашивает «Шығу керек пе? Өзгерістер сақталмайды» (`wizard.leave.*`). В конце — один вызов `createEvent` (+ `setupHall`, если зал задан). Так нет полусозданных событий |
| Шаг «Музыка» (6 / 8) | В Ф3 — только экран с «Кейін қосамын» и текстом `wizard.music.rights`. Загрузка, обработка и плеер (`#music-up` … `#music-ready`) — Ф5: там presigned-загрузка в R2 и ffmpeg. Кнопка загрузки скрыта флагом, пока нет Ф5 |
| Шаг «Шаблон» и предпросмотр на десктопе | 3 карточки со статичными мини-конвертами (SVG из дизайна, копии в приложении); выбор сохраняется в `events.template_id`. «Көру» и живой предпросмотр в рамке телефона — упрощённые: карточка с названием, датой и рестораном в цветах шаблона. Настоящий рендер приглашения подключается в Ф5 |
| Шаг «Текст» | Готовые тексты — данные в `src/domain/invitations/presets.ts` (kk № 1, № 3; ru № 1, № 2; для остальных типов — по одному). Места имён подсвечены, окончания хозяин ставит сам (правило падежей). Русский текст необязателен (`wizard.text.ruMissing`) |
| `#scope` | Если сессия `scope = 'events'` (вошёл по ссылке составителя), мастер не открывается: экран `wizard.needFullLogin.*` с кнопкой «SMS-кодпен кіру». Сервер в любом случае отклоняет `createEvent` (403) |
| Кто может создавать события на пилоте | `scope = 'all'` **и** номер в `allowed_owners` (ссылка основателя, поток 4) |

Если переход не произошёл, на карточке остаётся зелёная «WhatsApp-қа жіберу». Вопрос «Жіберілді ме?» для ссылки входа не задаём (А3) |
| Статус «Кірді · устройство · время» | Показывать только сессии, которым **это событие доступно** (`scope = 'all'` или событие есть в `session_events`). Устройства человека из чужих событий хозяину не раскрываются |
| «Құрылғылардан шығару» | `revokeMemberSessions` из Ф2: снимает доступ к этому событию у сессий по ссылкам. Подтверждение `members.card.signOutConfirm` |
| «Тойдан алып тастау» | `removed_at` + снятие события из `session_events` этого человека. Хозяина удалить нельзя (`ownerCannotRemove`). Гости, которых он добавил, остаются (`added_by_member_id` не меняется) |
| «Кім?» → права | Әкесі / Анасы → `parent` (рассадка и расходы включены); Жастар → `couple`; Басқа → `other` + поле подписи. Права по умолчанию по 5.3, хозяин может переключить. Категория по умолчанию: Әкесі → Өз туыстар, Анасы → Нағашылар, Жастар → Достар |

| «Кіреберіс сілтемесі» на экране составителей | Блок и действие `rotateDoorToken` делаются в Ф3, но **блок скрыт флагом до Ф8**: иначе хозяин отправит помощнику ссылку на страницу, которой ещё нет |
| `/join#switch` | Если на устройстве cookie сессии **другого** пользователя (другой телефон), то перед `consumeLink` — экран «Бұл телефонда басқа адам кірген» с «Жоқ, қалсын» (фокус) и «Иә, мен кіремін». Если тот же пользователь, событие добавляется в его сессию (Ф2) |
| Пометка «сынақ нұсқасы» | По ревью Ф1 П3: только хозяину; закрывается «✕»; закрытие помнится **на устройстве** (`localStorage` в `try/catch` — надёжнее, чем на сессию, как указано в макете); не показывается на «Зал», странице гостя, у помощника, на `/join` и `/login` |
| Категории события | `createEvent` создаёт 8 категорий по умолчанию: подписи kk и ru — значения `category.names.*` на момент создания (данные события, хозяин может переименовать), ранги 1…8, коды `kuda` … `baska` |

## 3. Задачи

### 3.1 Сервер (каждое действие: `authz` → zod)
- [ ] `createEvent`:
  - доступ — `requireUser` + `scope = 'all'` + `allowed_owners`;
  - вход: тип, `title` (как ввёл хозяин), `hosts_line?`, дата и время (`tz = Asia/Almaty`), ресторан, адрес, `map_url` (только `https://`, ошибка `wizard.venue.mapError`), тексты kk и ru, `template_id`;
  - в одной транзакции: событие, `door_token` (`randomToken`), хозяин в `event_members` (`role = owner`, `member_kind` по выбору хозяина или `parent`, права полные), 8 категорий;
  - `purge_after = starts_on + 90 дней` (Р8).
- [ ] Шаг «Зал»: `setupHall(eventId, {columns, tablesCount, seatsPerTable}, seatingVersion)` через `withSeating` (требует `seating`); лимиты 1–60 столов, 6–16 мест (zod и CHECK).
- [ ] `updateEvent(eventId, patch, version)` (`requireOwner`, 409) — для правок со шага обзора и из настроек.
- [ ] `addMember`, `updateMember`, `removeMember` (`requireOwner`); `addMember` сразу выпускает ссылку (`issueMemberLink`) и возвращает `waUrl`.
- [ ] `issueLoginLinkAction`, `revokeMemberSessionsAction` (есть с Ф2) — подключить к экрану.
- [ ] `rotateDoorToken` (`requireOwner`).
- [ ] Данные для экрана составителей: статусы `joined` / `notJoined` (сколько часов осталось) / `linkExpired`, последнее устройство и время — только по сессиям с доступом к событию.

### 3.2 Экраны (компоненты Ф1, тексты `content/messages`)
- [ ] `/e/new` — мастер «Жаңа той»:
  - 8 шагов и «Дайын!»;
  - прогресс «N / 8»;
  - одна задача на экран;
  - «Жалғастыру» внизу; «пропустить» — внутри шага;
  - на десктопе рейка шагов и предпросмотр (упрощённый, раздел 2);
  - все состояния макета 10, кроме музыкальных — они в Ф5.
- [ ] `/e` (список тоев): кнопка «Жаңа той» для тех, кто может создавать; после первого входа хозяина без событий — сразу мастер.
- [ ] `/e/[eventId]/settings/members` — «Тізімді кім толтырады» (макет 11): карточки, шторка «Адам қосу» (справа 480 px на ≥ 1024), подтверждения, тост «Ескі сілтеме жабылды». На телефоне вход через «⋯ → Баптаулар».
- [ ] `/join`: экран `#switch`; состояния «Сілтеме жарамсыз» уже есть.
- [ ] `PilotBanner` по правилу раздела 2.

### 3.3 Тесты
- [ ] **Integration:**
  - `createEvent` → 403 для `scope = 'events'` и без `allowed_owners`;
  - транзакция создаёт событие, хозяина, 8 категорий и `door_token`;
  - `setupHall` пишет `hall_tables` и `seating_changes`;
  - `addMember` → права по типу, дубль → ошибка;
  - `removeMember` снимает доступ, в том числе у сессии по ссылке;
  - статус устройств не показывает сессии без доступа к событию.
- [ ] **e2e (360 и 1440):**
  - хозяин по ссылке основателя проходит мастер — с залом и без;
  - добавляет «Анасы» → `href` у WhatsApp-перехода корректный → мама открывает ссылку в другом контексте браузера → «Кіру» → попадает в событие;
  - «Тек тізім» не видит кнопок рассадки;
  - «Жастар» не видят «Шығындар»;
  - сессия по ссылке на `/e/new` видит экран «нужен вход по SMS»;
  - `#switch`: на устройстве с сессией хозяина открыть ссылку мамы → вопрос → «Жоқ, қалсын» оставляет хозяина, «Иә» входит мамой;
  - пометка закрывается и не возвращается после перезагрузки.
- [ ] axe, 48 px, 130 % без поломок и без горизонтальной прокрутки на 320 и 360 — для мастера и экрана составителей.

## 4. Критерии приёмки

1. Мастер создаёт событие за один вызов; ничего не создаётся до «Дайын»; выход спрашивает подтверждение.
2. Зал в мастере необязателен; если задан — `hall_tables` и запись в истории через движок.
3. `createEvent` недоступен сессии по ссылке (сервер 403 + экран).
4. Составители: права по типу с пояснениями, ссылка через WhatsApp, статусы входа без раскрытия чужих устройств, «шығару» и удаление влияют только на это событие.
5. `/join#switch` защищает от случайной подмены пользователя на общем телефоне.
6. Пометка «сынақ нұсқасы» — по правилу раздела 2.
7. Экраны совпадают с макетами 10, 11 и 09#switch (360 и 1440, kk и ru, 130 %); axe без serious / critical.
8. Все проверки зелёные; тексты только из `content/messages`.
