## 1. Цель

Составитель ведёт список гостей на телефоне и отправляет приглашения через WhatsApp. Для этого нужны:
- «Менің тізімім» и списки других составителей;
- добавление, правка и удаление гостя (с «Қайтару»);
- защита от дублей;
- отправка через `wa.me` с подтверждением «Жіберілді ме?»;
- «Жауап бермегендер» с напоминаниями;
- ответ, принятый по телефону.

Все изменения, которые влияют на рассадку, идут через движок Ф7a на сервере.

**Не входит:** страница гостя и OG-картинка (Ф5); экран «Зал» (Ф7b); мастер события и составители (Ф3); итоги (Ф6).

## 2. Задачи

### 2.1 Серверный адаптер рассадки — `src/server/seating/`
- [ ] `withSeating(eventId, actor, fn)` по плану 7.1:
  1. транзакция и `select … from events where id = $1 for update`;
  2. загрузка состояния — зал (`hall_tables` + настройки), категории по `seating_rank`, активные семьи (`deleted_at is null`), `seq` = неизменный порядок вставки;
  3. вызов функции движка;
  4. запись изменённых семей по `deltas`;
  5. `seating_changes` с `buildDiff(before, after)` и `summary`;
  6. `events.seating_version += 1`.

  Возвращает `{ seatingVersion, changes, warnings, historyId? }` (план 6).
- [ ] Отображение «строка БД ↔ `Family` движка» и обратно (одно место, unit-тесты).
- [ ] `actor_kind`: `member` для действий составителя, `system` для автоматических размещений. Ответы по телефону — `member` с записью «Телефонмен жауап берді».

### 2.2 Действия (план 6.3) — каждое: `authz` → zod → адаптер / транзакция
- [ ] `addFamily`:
  - имя 1–80, телефон по желанию (`normalizePhone`; российские номера допустимы, `isKzMobile` **не** требуется);
  - категория, `expectedCount` 1–20;
  - `confirmNotDuplicateOf?`.

  Ответ: `{family, placement?}` | `{conflict: 'phone', existing}` (блок, текст «Бұл нөмір Анасының тізімінде бар») | `{conflict: 'similar', candidates}` (шторка «Бұл сол адам ба?», `dupPairs`/`similar` из `@/domain/guests/duplicates`). Токен гостя — `randomToken()`. Если зал настроен — `addFamily` движка (размещение).
- [ ] `updateFamily(familyId, patch, version)`: оптимистичная блокировка по `families.version` (409 с понятным текстом). Изменение мест или категории идёт через движок (`setSeats`; смена категории рассаженных не двигает).
- [ ] `deleteFamily` / `restoreFamily`: мягкое удаление, движок `removeFamily` / `restoreFamily`; тост 8 с с «Қайтару».
- [ ] `markSent(familyId, kind)` и поток «Жіберілді ме?» (план 6.3, DESIGN 8.5):
  - нажатие «WhatsApp-қа жіберу» пишет `activity_log.wa_clicked` и запоминает семью (`sessionStorage`, в `try/catch`);
  - при `visibilitychange → visible` открывается шторка «Шақыруды WhatsApp-та жібердіңіз бе?» с «Иә, жіберілді» (фокус) и «Жоқ, әлі жібермедім»;
  - если человек закрыл шторку без ответа, на карточке остаётся строка с той же кнопкой.
- [ ] `recordAnswerByMember(familyId, attending, seats?)` → движок `setRsvp`, `answered_by = 'member'`.
- [ ] `createCategory` (S3; русское название необязательно, Д4/11; место в порядке — «после …»).
- [ ] `keepBothDuplicates` → `duplicate_reviews`.
- [ ] Тексты WhatsApp: `wa.invite` и `wa.remind` из `content/messages` с `{kind}`, `{hasHosts}`, именем в именительном падеже и ссылкой `APP_URL/i/{token}`. Целиком в `encodeURIComponent`. Без телефона — `https://wa.me/?text=…`.

### 2.4 Тесты
- [ ] **Integration:**
  - каждое действие: доступ (чужой → 403, сессия `scope = 'events'` чужого события → 403);
  - дубль по телефону блокируется уникальным индексом с понятным ответом;
  - `version` → 409;
  - адаптер: блокировка события; два одновременных `addFamily` в один зал не создают переполнения сверх правил движка;
  - запись `seating_changes`; `seating_version` растёт;
  - удаление и восстановление возвращают на прежний стол, если места свободны.
- [ ] **e2e (360 и 1440):**
  - добавить гостя → карточка подсвечена;
  - дубль по телефону и по имени;
  - «WhatsApp-қа жіберу» — проверить `href` ссылки `wa.me`, имитировать возврат (`visibilitychange`) → «Жіберілді ме?» → «Жіберілмеген» становится «Жауап жоқ»;
  - «Телефонмен жауап берді»;
  - удаление и «Қайтару»;
  - «Жауап бермегендер».
- [ ] Производительность: 65 семей сида < 1 с до интерактивности на мобильном профиле (Playwright + троттлинг CPU ×4).

## 3. Критерии приёмки

1. Дубль по телефону сохранить невозможно; при похожем имени решает составитель.
2. Каждое изменение мест, ответа, удаление и восстановление проходит через адаптер: блокировка события, движок, `seating_changes`, `seating_version`. **Рассаженные семьи не двигаются**: integration-тест на сидах с настроенным залом.
3. Поток «Жіберілді ме?» работает как в 2.2; `sent_at` ставится только после «Иә».
4. Тексты WhatsApp — из `content/messages`, без склонения имён; ссылка гостя ведёт на `/i/{token}`. Страница гостя — Ф5; до неё ссылка может отдавать 404.
5. Экраны совпадают с макетами 01 и 02 (360 и 1440, kk и ru), axe без serious / critical, цели ≥ 48, 130 % без поломок.
6. 65 семей < 1 с; все проверки зелёные.
7. Короткая проверка с человеком 50+ на локальном сервере (по возможности — с родителями семьи-пилота): добавить 3 гостей и отправить одно приглашение без подсказок. Заметки — в handover.
